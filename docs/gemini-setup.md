# Gemini: activate only after free-tier access is verified

## Current status

September 27 local update: Panoramic AI's **Chat** tab now sends explicit questions to Gemini through the server, including in recorded-demo mode. Demo replies are no longer generated by local keyword rules. The new `demo_assistant` operation accepts only a bounded, suite-scoped text snapshot, validates suite/record IDs, rebuilds citations, and permits no actions. It never reads authenticated care records; the existing signed-in `assistant` operation keeps its separate authorization checks.

September 29 verification: Gemini 3.8 Flash again returned HTTP 503 `UNAVAILABLE`. The default was changed to `gemini-3.5-flash-lite`; the candidate handler then returned a real, cited answer in 9.272 seconds. After promotion, a separate request to production `https://panoramic-app.vercel.app/api/gemini` returned HTTP 200 with a cited, no-action answer in 1.265 seconds. Both used only a synthetic A101 text snapshot and the existing Vercel-held secrets. No credentials were downloaded or saved, and billing was not changed. These are individual connectivity results, not latency guarantees or visual-accuracy measurements. Local `.env.local` still has no Gemini settings.

Earlier attempts on September 26–27 failed with provider unavailability/timeouts despite all configuration checks passing. Those failures were not proof that paid access was required. The September 29 checks above verify text chat, not staged-frame analysis or an accuracy evaluation.

## Account setup (owner action)

1. Open https://aistudio.google.com/api-keys with an eligible Google account you own. If access redirects to requirements, follow Google's account guidance; do not bypass regional or age restrictions. A different eligible personal account may be used if you own it. Complete private sign-in/verification yourself.
2. Create or choose a project visibly marked **Free Tier**. Do not link a billing account, buy credits, or upgrade a subscription for this test.
3. Create a Gemini API key. Keep it private. Note the **Project Number** separately for the ShellHacks Gemini prize field; it is not the API key.
4. Confirm the selected model is available with free quota in this project. Current default is `gemini-3.5-flash-lite`, which Google's pricing lists with a free tier. Change `GEMINI_MODEL` if needed after rechecking official model availability and pricing.

## Server configuration

In local `.env.local` or the Panoramic Vercel project's private environment settings, set:

```dotenv
GEMINI_API_KEY=<private key from the verified Free Tier project>
GEMINI_MODEL=gemini-3.5-flash-lite
GEMINI_FREE_TIER_CONFIRMED=true
GEMINI_DEMO_ACCESS_CODE=<a separate randomly generated private value of at least 16 characters>
```

Never prefix these with `VITE_`. Do not commit them, expose them in screenshots, enter the Google key into the app's access-code field, or paste secrets into chat. `GEMINI_FREE_TIER_CONFIRMED` is only the owner's attestation; it cannot prevent charges if the key actually belongs to a paid project. Keep billing disabled at Google. The app contains no billing or upgrade calls.

Restart `npm run dev` after local environment changes. Redeploy the Vercel project after changing its server environment variables. Check `/api/gemini`: `configured: true` means the server has its required settings, **not** that a live provider call succeeded.

## Panoramic AI chat

1. Open **Resident Floor → select a suite → Chat**. Choose all demo records for that suite, or one concern.
2. Enter the separate **Gemini workspace access code**, not the Google API key or ElevenLabs station code, and verify access. It stays in the mounted workspace's memory across suites and tabs; refreshing or forgetting access clears it. It is not saved to local/session storage.
3. Confirm that the question and selected text contain no sensitive resident information. On the free tier, Google may use content to improve its products. Use only the synthetic demo, not real resident records or care footage.
4. Send a question. A successful answer shows Gemini provenance, a timestamp and expandable source citations. Questions are sent individually with the current snapshot, not as continuous background requests. Changing data requires asking again.
5. No provider failure falls back to canned text. Quota errors stop without retrying or upgrading billing. Server throttling remains per instance, not a durable spending cap.
6. Chat has no write tools. Assignment, acceptance, arrival, and station sign-offs remain in the existing human-operated response workflow. Station announcements remain independent of chat.

## Private deployment verification

Ordinary builds do not call Gemini. An explicitly authorized release can set the **build-only** variable `PANORAMIC_VERIFY_GEMINI=candidate` to make one synthetic, suite-scoped request through the candidate server handler before building. A failed or uncited response stops deployment. This works with Vercel-held secrets without downloading them or adding any diagnostic HTTP endpoint.

After publication, `PANORAMIC_VERIFY_GEMINI=production` in an unpromoted verification build makes one request to the fixed production `/api/gemini` endpoint. Both modes retain access-code, consent, free-tier, citation and no-action checks. They log only the fictional test answer and outcome, never credentials. Neither mode retries automatically or changes billing. Do not persist the verification flag in project settings.

The default Flash-Lite model uses its supported `MINIMAL` thinking level for short responses. Other Gemini 3 overrides use `LOW` (Gemini 3.8 rejects `MINIMAL`); older model overrides omit this setting. Server generation is bounded to 35 seconds, chat to 45 seconds, and access checks to 12 seconds. A failed question can be restored for an explicit resubmission, not silently retried.

## First live test

1. Use a non-sensitive photo of staged props in an empty room. Do not upload real care footage.
2. Enter the separate private demo code; check the staging confirmation; click **Analyze frame with Gemini** once.
3. Confirm the app reports a Gemini response, a model identifier, timestamp, and scene observations. Inspect each box and statement manually against the photo. An error must not create a result or certify safety.
4. Test an ordinary cup with no visible spill, a spill-like patch, a box across a walking route, and poor lighting. Record misses and false positives. The fixture tests do not measure visual accuracy.
5. For a candidate hazard, demonstrate no available caregiver, then an available qualified caregiver, acknowledgment, arrival, and a specific resolution note. Only then request and review the optional Gemini summary.
6. Watch Google's quota. If exhausted, wait or shorten the demonstration; do not enable billing automatically. The local throttle is per instance, not a durable global spending cap.
